Clearing a 7,500-document backlog with an unattended extraction pipeline

A regulator couldn't keep up with incoming submissions, let alone the backlog. I designed and built a pipeline on Azure that reads each document, extracts the data and writes it to SQL, with people only handling the exceptions.

Architecture

Five managed services, no servers to look after.

The problem

A backlog of around 7,500 documents, and new ones arriving faster than the team could key them in. Every document needed the same structured fields captured into a database before work on it could start.

What I did

Designed an event-driven pipeline: Event Hub takes each document in, a Logic App orchestrates, Azure Content Understanding with a GPT model extracts the fields, and an Azure Function turns the output into SQL for Azure SQL Database.

We started with small batches, checked the output by hand, and increased volume only as confidence in extraction quality grew. Anything the pipeline couldn't handle cleanly went to a person rather than into the database.

Outcome

The backlog was cleared over six months and the process now runs largely unattended. Roughly nine in ten documents flow from ingestion to SQL untouched; the rest are genuine edge cases. Running cost is about £200 a month for everything.

What I'd do next

Capacity sits far above real intake, so a tuning review to right-size the pipeline, and its cost, was the planned next step.
